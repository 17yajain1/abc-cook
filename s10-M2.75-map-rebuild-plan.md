## 3. Conflicts found and resolved (owner decision via AskUserQuestion)

Dry-ran the handoff's classification rule against the real `.plan.json` output for all
five fixtures (script run inline, not committed) before writing any code, per the brief's
own "do not tune only against Kadai Paneer" instruction. Found:

| # | Conflict | Decision |
|---|---|---|
| 1 | Biryani: `soak_rice` (window host, 4 members) ties at `start_min=0` with `boil_spiced_water` (no window) under the handoff's literal `currentEnd` walk — whichever loses becomes a right-column card with nowhere to draw its bracket, contradicting "a window host is always mainline." | **Seed window hosts onto the mainline first**, then walk the remaining candidates against those reserved intervals. Still pure interval math, no per-task flag. |
| 2 | The handoff defines one 108px-wide right column with only a per-window overflow rule (`members.length > 3`); Biryani's right column has 8 pairwise time collisions from independent-overlap cards on top of window children. | **Keep two columns; add a generic fold rule.** Window children outrank independents; any right-column card that would collide in time folds into the existing quiet `+N more` label instead of a third lane. |
| 3 | "Solid line between consecutive mainline cards" (design handoff) vs. "one edge per actual `depends_on` pair" (implementation handoff's own test list) — Kadai's consecutive mainline pair `saute_onion → chop_tomato` is not a dependency, so a literal chain would draw a false one, which `CLAUDE.md` forbids. | **Solid arrows only for real `depends_on` pairs where both ends are mainline.** No arrows into/out of right-column cards. |
| 4 | The handoff's geometry leaves no left gutter for a time axis; `DESIGN_SYSTEM.md`'s current Map grammar and the s9 mock have one at x=56 with tick labels. | **No axis, no ticks.** Time is carried by vertical order, sqrt-compressed height, and each card's own duration label. |

Micro-resolutions not put to the owner (flagged for the CP1 report instead): "cap at 3
lines" vs. "never clip a word" (never-clip wins — clipping is in the handoff's own
rejected list); the bracket colour `#a39d8f` isn't a written token, so it renders as
